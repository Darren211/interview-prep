# MySQL 事务与锁面试题

## 事务的 ACID 特性是什么？

原子性、一致性、隔离性、持久性。InnoDB 通过 undo、redo、锁与 MVCC 等机制共同实现相关保证；不能把每个 ACID 属性简单对应到单一机制。

## MySQL 的隔离级别有哪些？

读未提交、读已提交、可重复读、串行化。不同隔离级别对并发事务可见性和锁行为不同。InnoDB 默认通常是可重复读，但应用可配置修改。

## 脏读、不可重复读和幻读是什么？

脏读是读取其他事务尚未提交的数据；不可重复读是在同一事务中重复读取同一行得到不同已提交值；幻读是同一范围查询重复执行时，匹配的行集合发生变化。具体防护取决于隔离级别、快照读/当前读及锁。

## redo log、undo log、binlog 有什么区别？

- **redo log**：InnoDB 的重做日志，用于崩溃恢复和持久性保障。
- **undo log**：保存旧版本信息，支持事务回滚和 MVCC 读视图。
- **binlog**：MySQL Server 层的变更日志，常用于复制和时间点恢复。

## MVCC 如何提供一致性读？

InnoDB 通过行版本信息、undo 版本链和 Read View 判断事务可见的版本。读已提交通常每次一致性读创建新的 Read View；可重复读通常在事务第一次一致性读时建立并复用快照，当前读则可能使用锁。

## InnoDB 有哪些锁？行锁如何实现？

常见有共享锁、排他锁、意向锁、记录锁、间隙锁和 next-key lock 等。锁通常围绕索引记录和范围实现；缺少合适索引可能扩大锁定范围。回答应说明隔离级别和 SQL 类型。

## 死锁产生的必要条件是什么？

互斥、占有并等待、不可剥夺、循环等待。数据库遇到死锁通常会检测并回滚其中一个事务；应用应保持事务短小、统一加锁顺序，并对可重试错误设计安全重试。

## 如何排查和优化慢 SQL？

先确认业务查询和结果正确，查看慢查询日志并使用 `EXPLAIN`/`EXPLAIN ANALYZE` 检查访问路径、扫描行数、索引选择和排序临时表，再根据数据分布调整索引、SQL 或表设计，并用真实负载验证。

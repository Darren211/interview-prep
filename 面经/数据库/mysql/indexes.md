# MySQL 索引面试题

## 索引有什么优缺点？

索引能减少查找数据的工作量，但会占用存储空间，并增加写入、更新和维护成本。是否更快要看选择性、数据规模、查询形态和执行计划。

## MySQL 索引有哪些常见分类？

按约束可分普通、唯一、主键索引；按列数可分单列和联合索引。InnoDB 中聚簇索引决定行数据的组织方式，二级索引叶子通常保存主键值，必要时再通过主键查整行（回表）。不要说 InnoDB 的所有索引都是非聚簇索引。

## 为什么 InnoDB 常用 B+ 树？

B+ 树扇出高、树高较低，减少磁盘页访问；叶子节点有序且便于范围扫描。哈希适合等值查找但不擅长范围和排序；普通二叉树高度可能退化；B 树内部节点也保存数据，范围扫描与页组织通常不如 B+ 树适合数据库索引。

## 什么是回表和覆盖索引？

二级索引找到主键后，再访问聚簇索引取得所需列，称为回表。如果查询所需列都能从索引中取得，则为覆盖索引，可避免回表。

## 什么是索引下推？

Index Condition Pushdown 让存储引擎在读取完整行之前，先利用索引列过滤条件，减少回表次数。是否使用由查询条件、索引结构和优化器决定。

## 什么是联合索引的最左前缀原则？

联合索引 `(a,b,c)` 通常可用于从 `a` 开始的连续前缀条件，例如 `a`、`a,b`、`a,b,c`。范围条件、排序和条件组合会影响后续列的使用，需用 `EXPLAIN` 验证，不能简单断言某列之后“一定不走索引”。

## 创建索引要注意什么？

结合真实查询的过滤、连接和排序条件设计；关注选择性、列宽、联合索引顺序和写入成本；避免重复索引。用执行计划和慢查询验证收益。

## 常见索引未被使用的原因有哪些？

可能包括对索引列使用函数或表达式、前置通配符模糊匹配、隐式类型转换、低选择性、条件组合不符合索引前缀、统计信息或成本估算结果等。`OR`、`!=` 并非在所有情况下都必然导致索引失效，应看执行计划。

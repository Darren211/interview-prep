# TCP、UDP 与 HTTP 面试题

> 原始总结列出了主题和少量 TCP 笔记，以下补成可复习的回答框架；HTTP/2、TLS 等细节可继续结合学习笔记补充。

## TCP 与 UDP

### TCP 三次握手的目的是什么？

三次握手让双方确认彼此的发送和接收能力，并协商初始序列号等连接状态。客户端发送 SYN，服务端以 SYN/ACK 响应，客户端再发送 ACK。序列号用于可靠传输中的排序与确认，不能只说“解决乱序”。

### TCP 为什么需要四次挥手？

TCP 是全双工连接，两个方向需要分别关闭。主动关闭方发送 FIN，对端 ACK 后仍可继续发送数据；当对端也完成发送时再发 FIN，主动关闭方最后 ACK。具体状态迁移与 TIME_WAIT 的作用应结合连接关闭场景说明。

### SYN、ACK、序列号分别是什么？

SYN 用于同步连接序列号，ACK 表示确认号有效；序列号标识字节流中的位置，确认号表示期望收到的下一个字节。TCP 可靠、有序、面向连接；UDP 无连接、开销较小，不保证送达、顺序或去重。

## HTTP 与 WebSocket

### HTTP、HTTPS、HTTP/2 有什么关系？

HTTP 是应用层协议。HTTPS 是在 HTTP 通信中使用 TLS 保护传输安全。HTTP/2 在同一连接上支持多路复用、头部压缩等机制；实际部署中 HTTP/2 通常与 TLS 配合使用。比较时应分别说明协议语义、连接复用和安全层。

### WebSocket 适用于什么场景？

WebSocket 通过 HTTP 握手升级为持久的全双工连接，适合服务端需要主动推送、双方频繁交换消息的场景，例如实时通知和协作应用。需要同时考虑心跳、断线重连、鉴权、扩展和水平扩展时的消息路由。

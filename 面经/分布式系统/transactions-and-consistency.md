# 分布式系统面试题

## 两阶段提交、三阶段提交和 TCC 有什么区别？

- **2PC**：协调者先 prepare，再决定 commit/rollback。参与者可能在等待协调者时阻塞，协调者故障会影响可用性。
- **3PC**：增加预提交阶段并引入超时，试图减少阻塞；在网络分区等异步环境下仍不能简单保证完美一致性。
- **TCC**：业务实现 Try、Confirm、Cancel 资源预留与提交/补偿，灵活但开发成本高，需处理幂等、空回滚和悬挂。

消息表、事务消息、Saga 等方式适合不同的一致性和可用性要求。方案需说明补偿、重试、幂等和对账机制。

## 如何生成分布式唯一 ID？

可使用 Snowflake 类方案，将时间、机器标识和序列号组合。需处理时钟回拨、机器 ID 分配、位数规划、序列耗尽和趋势递增等问题；也可评估数据库号段或集中式服务。

## 分布式环境如何保证业务幂等？

用业务唯一键或幂等 token 建立去重记录，并让“检查与写入”具备原子性；必要时使用唯一约束、状态机或条件更新。缓存锁不能替代持久层幂等约束。

## 多个请求争抢同一资源如何保证只成功一个？

可使用数据库条件更新/唯一约束，或 Redis 原子操作/分布式锁。选择方案时分析数据权威所在、竞争范围、锁过期、重试和失败恢复。文档中的骑手抢单场景可从订单状态条件更新开始设计。
